الربط بين Architecture ومشاريع التنفيذ عبر Architecture Contract، توجيه Deployment، مراجعات Compliance، إدارة Change Requests، تجهيز Business وIT Operations، وتحويل الحل المنشور إلى Baseline جديدة.

Phase G — Implementation Governance

Ensure that implementation delivers the approved Target Architecture.

Study Chapter 13

1. موضع Phase G والغرض منها

Architectural Oversight of Implementation
⌄

تأتي Phase G: Implementation Governance بعد اعتماد Architecture Roadmap وImplementation and Migration Plan في Phase F. في هذه المرحلة تبدأ مشاريع التطوير والتنفيذ الفعلية، بينما تمارس Architecture Function الرقابة لضمان أن الحلول المنفذة تظل متوافقة مع Target Architecture.

Phase FApproved plan, projects, priorities, costs, transitions.
→
Phase GArchitecture Contract, guidance, compliance reviews, operations readiness, deployment oversight.
→
Phase HManage changes to the deployed architecture and the Architecture Landscape.
Phase G لا تستبدل Development Process. التطوير يحدث بالتوازي داخل منهج المؤسسة، بينما Phase G توفر Architecture Governance.

2. Objectives — أهداف Phase G

Conformance and Governance of Implementation-Driven Change
⌄

Ensure Conformance

التأكد من التزام Implementation Projects بالTarget Architecture والمتطلبات والمبادئ والمعايير المتفق عليها.

Perform Architecture Governance

تنفيذ المراجعات والقرارات والاستثناءات والتصعيدات اللازمة للحل الجاري تنفيذه.

Implementation-Driven Change Requests

قد يكشف التنفيذ أن Requirement غير ممكنة، أوأن Standard تغيرت، أوأن Solution أفضل متاحة. لا تُقبل التغييرات بصورة غير رسمية؛ تُسجل كChange Requests وتُقيّم وفق Governance.

3. Inputs — مدخلات Phase G

Approved Architecture, Governance, Contract, Roadmap, and Migration Plan
⌄

External & Non-Architectural

  • Architecture Reference Materials.
  • Request for Architecture Work.
  • Capability Assessment.

Architecture Direction

  • Statement of Architecture Work.
  • Architecture Vision.
  • Architecture Definition Document.
  • Architecture Requirements Specification and Gap Results.
  • Architecture Roadmap.

Governance & Delivery

  • Architecture Governance Framework.
  • Implementation Governance Model.
  • Standard Architecture Contract.
  • Implementation and Migration Plan.
  • Organizational Model, tailored method, tools, and Repository.
Phase G تبدأ من Architecture معتمدة وخطة تنفيذ معتمدة؛ لا تبدأ من فكرة غير محددة كما في Phase A.

5. Confirm Scope and Priorities for Deployment

Align Development Management with the Approved Migration Outputs
⌄

Review Migration Outputs

تأكيد Work Packages وProjects وTransitions والتسلسل والنتائج المتوقعة.

EA Priorities

تحديد ما يجب على Development Teams حمايته أولًا: shared services، standards، critical data، security، interoperability.

Deployment Issues

كشف القيود أوالتعارضات أوالتبعيات التي تحتاج توصية معمارية.

Building Block Lifecycle

تحديد ABBs وSBBs التي ستُنشأ أوتُحدّث أوتُستبدل أوتُسحب.

7. Identify Deployment Resources and Skills

Educate Delivery Teams and Select Development Methods that Interoperate with Architecture Outputs
⌄

Development Skills

Software، data، integration، infrastructure، testing، security، and business change.

Architecture Literacy

فهم Target، Principles، Standards، ABBs، acceptance criteria، and compliance expectations.

Methods & Tools

اختيار Development Method يمكنه استهلاك Architecture Artifacts وربط Models بالتصميم والتنفيذ.

Feedback Mechanism

يجب أن يسمح المنهج بإعادة Feedback وDesign Decisions وChange Requests إلى Architecture Team.

Architecture handover ليس إرسال PDF فقط؛ يجب تمكين الفريق من فهم القرارات والقيود وكيفية طلب التغيير.

8. Architecture and Development Run in Parallel

The Architecture Team Governs while the Development Process Builds
⌄
Architecture Governance LaneContract, recommendations, compliance, dispensations, Change Requests, repository.
↔
Shared Decision & EvidenceImpact analyses, designs, tests, acceptance criteria, risk, performance evidence.
↔
Development / Deployment LaneDesign, build, configure, test, train, deploy, operate.

مستوى مشاركة Architects المباشرة في التنفيذ يختلف حسب Organizational Policy، لكن مسؤولية Conformance تبقى واضحة.

9. Guide Development of Solutions Deployment

Formulate Recommendations for Every Implementation and Deployment Project
⌄

لكل Project منفصل، توثق Architecture Team توصياتها داخل Impact Analysis.

Project Scopeما الذي سيبنيه المشروع وما يقع خارجه؟
Strategic Requirementsالمتطلبات المعمارية التي لا يجوز فقدها أثناء Solution Design.
Conformance RulesStandards، interfaces، principles، quality attributes.
Roadmap Timelineمواعيد Transition وDependencies والMilestones.
Change Requestsأي انحراف مطلوب مثل دعم Standard Interface جديد.
Acceptance Criteriaالأدلة المطلوبة لإثبات الالتزام.
Risk & Issuesمخاطر الانحراف أوالتأخر أوالتعارض مع مشاريع أخرى.

10. Architecture Contract

The Formal Link between Architecture and the Implementation Organization
⌄
Architecture FunctionTarget, requirements, principles, standards, compliance criteria.
⇄
Signed Architecture ContractResponsibilities, deliverables, measures, acceptance, reporting, change and dispensation rules.
⇄
Developing & Sponsoring OrganizationsCommitment to delivery, evidence, governance, and escalation.

يُوقّع العقد من جميع Developing Organizations والجهة الراعية. قد يكون وثيقة قانونية أوGovernance Agreement داخليًا حسب المؤسسة.

11. What the Architecture Contract Should Control

Scope, Deliverables, Measures, Acceptance, Risks, and Change
⌄

Identity

Name، description، objectives، owners.

Delivery

Scope، deliverables، constraints، timeline.

Quality

Measures of effectiveness، architecture criteria، acceptance evidence.

Governance

Reviews، reporting، escalation، decision rights.

Change

Change Request process، impact analysis، approval.

Risk

Risks، issues، assumptions، dependencies، dispensations.

12. Guide Business and IT Operating Models

Design How the Deployed Services Will Be Operated for Their Full Life
⌄

Business Operations

Roles، processes، ownership، service delivery، controls.

IT Operations

Support، monitoring، incident، change، capacity، continuity.

Service Requirements

Availability، performance، security، recovery، support hours.

Operational Gap Analysis

مقارنة Solution Architecture مع قدرة التشغيل الحالية وتحديد ما يجب بناؤه قبل Go-Live.

حل متوافق في التصميم لكنه غير قابل للتشغيل أوالدعم لا يُعد Implementation ناجحة.

15. Architecture Compliance Is Broader than a Final Audit

Continuous Governance across Design, Build, Test, and Deployment
⌄

Design Review

قبل أن يصبح الانحراف مكلفًا، تُراجع Solution Architecture والتصميم.

Build Review

متابعة Building Blocks وinterfaces والstandards أثناء التنفيذ.

Pre-Deployment Review

التأكد من الاختبارات والعمليات والSLAs والacceptance.

Post-Development Review

إغلاق جزء التطوير وتوثيق الواقع المنفذ والاختلافات.

16. Implementation-Driven Change Requests

Route Necessary Change without Allowing Uncontrolled Architecture Drift
⌄
Implementation DiscoveryConstraint, new standard, product limitation, better solution, risk, or dependency.
→
Impact Analysis & GovernanceDoes it affect project design, Target Architecture, roadmap, principles, or other projects?
→
DecisionApprove solution change, grant dispensation, update architecture, or reject.

التغيير المقبول قد يؤدي إلى تحديث Architecture Definition Document أوRequirements أوVision بعد التنفيذ، أوإلى Request for Architecture Work جديدة.

17. Implement Business and IT Operations

Deploy Services, Skills, Training, and Communications—not Technology Alone
⌄

IT Service Delivery

Deploy infrastructure، applications، data services، monitoring، and support.

Business Service Delivery

تشغيل العمليات والأدوار والسياسات والخدمات الجديدة.

Skills & Training

تأهيل المستخدمين وSupport Teams وOperational Owners.

Communication & Documentation

نشر تعليمات التشغيل والخدمة والسياسات والتغيير.

19. Perform Post-Implementation Review and Close

Confirm Outcomes, Capture Lessons, Publish Reviews, and Close Projects
⌄
ReviewArchitecture conformance, business outcomes, service performance, residual issues.
→
Capture & PublishLessons learned, compliance results, change requests, updated documents and baseline.
→
CloseFormal project closure when the solution is fully deployed.
Closure لا تعني انتهاء Architecture Lifecycle؛ تنتقل المسؤولية إلى التشغيل وPhase H لإدارة التغيير المستمر.

21. Approach — Deliver through Transitions and Existing Governance

Incremental Benefit, Phased Deployment, Portfolio Management, and Long-Life Operations
⌄

Implementation Program

ينفذ Transition Architectures المتفق عليها في Migration Planning.

Phased Deployment

يعكس Business Priorities الموجودة في Architecture Roadmap.

Corporate / IT / Architecture Governance

تُستخدم الأطر المؤسسية القائمة بدل إنشاء مسار منفصل.

Portfolio / Program Management

تنسيق التمويل والاعتماديات والموارد والتقارير.

Operations Framework

Enterprise-Wide Compliance

22. Phase F vs. Phase G vs. Phase H

Plan, Govern Delivery, then Manage Change
⌄

Phase F — Migration Planning

تحدد الأولوية والموارد والتكلفة والتوقيت وتنتج Approved Implementation and Migration Plan.

Phase G — Implementation Governance

تربط Architecture بمشاريع التنفيذ عبر Contract ومراجعات Compliance والعمليات.

Phase H — Change Management

تدير التغيير بعد النشر وتقرر إن كان يحتاج تعديلًا بسيطًا أودورة ADM جديدة.

Development Process

هو الذي يصمم ويبني ويختبر وينشر فعليًا بالتوازي مع Phase G.

23. Conformance vs. Compliance Review vs. Acceptance

Related but Different Governance Ideas
⌄

Conformance

درجة تطابق الحل مع Target Architecture والمتطلبات والمبادئ والمعايير.

Compliance Review

عملية رسمية لجمع الأدلة وتقييم Conformance وتحديد الإجراءات.

Acceptance Criteria

شروط قابلة للتحقق تحدد متى يُقبل Deliverable أوSolution.

Dispensation

إذن رسمي بانحراف محدد ومشروط، وليس إعلانًا بأن الحل متوافق بالكامل.

24. Example Governance Decisions

How to Respond to Common Implementation Situations
⌄

Vendor Product lacks a Standard Interface

قيّم أثره؛ اطلب Adapter/SBB، غيّر Product، أوقرر Dispensation محددة بزمن وخطة خروج.

Project Proposes a Better Technology

لا تُرفض لأنها مختلفة فقط. نفذ Impact Analysis وقدّم Change Request لتحديث Target إذا كانت القيمة والمخاطر مبررة.

Shared Service Delayed

راجع Dependencies؛ امنع إنشاء بدائل دائمة مكررة، أووافق على Interim Solution مرتبطة بTransition واضحة.

Operational Team Cannot Support the Solution

أضف Work Package للskills/monitoring/support أوأجل Go-Live؛ المشكلة Architecture/Operations Gap وليست تدريبًا بسيطًا فقط.

26. مراجعة الامتحان والأسئلة التفاعلية

Part 1 Focus, Common Traps, and 30 Practice Questions
⌄
Phase G vs Development

G تحكم وتراجع؛ Development Process يبني وينشر.

Conformance vs Review

Conformance حالة؛ Compliance Review عملية تقييم.

Architecture Contract vs Project Charter

Contract تربط Architecture Governance بالتنفيذ؛ Charter يؤسس المشروع إداريًا.

Recommendation vs Dispensation

Recommendation تطلب تصحيحًا؛ Dispensation تقبل انحرافًا رسميًا ومشروطًا.

Change Request vs Unauthorized Drift

الأولى محكومة وقابلة للتتبع؛ الثانية انحراف غير مقبول.

Deployment vs Operations

Go-Live ليس النهاية؛ يجب إنشاء Operating Models وSLAs وSupport.

Repository vs CMDB

Repository تحفظ Architecture Knowledge؛ CMDB تحفظ Operational Configuration، ويجب تحديثهما.

Phase G vs Phase H

G أثناء التنفيذ والنشر؛ H تدير التغيير المستمر بعد النشر.

خريطة الحفظ:
Scope & Priorities → Resources → Deployment Guidance → Contract → Compliance → Operations → New Baseline → Review & Close → Phase H.
