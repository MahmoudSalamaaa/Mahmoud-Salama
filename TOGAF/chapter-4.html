A — Architecture Foundations

Definitions 4.1–4.9 — التجريد والفاعلون والتطبيقات والمعمارية وABB
⌄
4.1

Abstraction

التجريد

تقنية لتلخيص أو تعميم المحتوى المعقد، أو تثبيت مستوى موحد من التفاصيل حتى يصبح التحليل والتواصل واتخاذ القرار ممكنًا.

مثال: عرض خريطة قدرات الأعمال أولًا، ثم فتح تفاصيل كل قدرة عند الحاجة.
تمييز مهم: لا يعني حذف التفاصيل نهائيًا؛ بل تأجيل غير الضروري منها إلى المستوى المناسب.
4.2

Actor

الفاعل

شخص أو جهة أو نظام يؤدي دورًا واحدًا أو أكثر ويبدأ نشاطًا أو يتفاعل معه، وقد يكون داخليًا أو خارجيًا.

مثال: المورد Actor خارجي، وموظف المشتريات Actor داخلي، ونظام الدفع قد يكون Actor تقنيًا.
تمييز مهم: Actor هو من يؤدي السلوك؛ Role يصف الدور المتوقع منه.
4.3

Application Architecture

معمارية التطبيقات

وصف بنية التطبيقات وتفاعلاتها وكيف تدعم قدرات الأعمال وتدير أصول البيانات.

مثال: خريطة توضح ERP وCRM ومنصة المشتريات وروابط التكامل بينها.
تمييز مهم: لا تقتصر على قائمة التطبيقات؛ تشمل العلاقات والخدمات والمسؤوليات.
4.4

Application Component

مكوّن تطبيقي

وحدة وظيفية مغلفة، معيارية وقابلة للاستبدال، تضم سلوكًا وبيانات وتقدم خدمات عبر Interfaces.

مثال: مكوّن إدارة العقود أو مكوّن إدارة أوامر الشراء داخل منصة أكبر.
تمييز مهم: قد يكون تطبيقًا كاملًا أو جزءًا منه، ويعتمد على Technology Services.
4.5

Application Platform

منصة التطبيقات

مجموعة مكونات Hardware وSoftware التي توفر الخدمات التقنية اللازمة لتشغيل التطبيقات.

مثال: منصة حاويات، Runtime، Database، Messaging، وخدمات مراقبة تشغّل التطبيقات.
تمييز مهم: المنصة تمكّن التطبيقات؛ ليست هي التطبيق التجاري نفسه.
4.6

Application Service

خدمة تطبيقية

سلوك آلي محدد يمكن طلبه من تطبيق، ويدعم جزءًا من Business Service أو كلها.

مثال: خدمة التحقق من رصيد المخزون أو إصدار فاتورة إلكترونية.
تمييز مهم: Service هو السلوك المتاح؛ Component هو الوحدة التي تنفذه.
4.7

Architectural Style

أسلوب معماري

مجموعة خصائص ومبادئ تميز طريقة تشكيل Architecture في سياق معين وتوجهها أو تقيدها.

مثال: Microservices، SOA، Event-Driven، أو Zero Trust.
تمييز مهم: Style ليس Framework كاملًا؛ هو طريقة أو خصائص لتشكيل Architecture.
4.8

Architecture

المعمارية

المفاهيم والخصائص الأساسية للنظام في بيئته، أو بنية مكوناته وعلاقاتها والمبادئ التي تحكم تصميمه وتطوره.

مثال: معمارية سلسلة التوريد تربط العمليات والبيانات والتطبيقات والتكنولوجيا.
تمييز مهم: TOGAF يستخدم معنى مفاهيميًا ومعنى بنيويًا متكاملين.
4.9

Architecture Building Block (ABB)

لبنة بناء معمارية

مكوّن منطقي أو مستقل عن المورد يحدد ما المطلوب من Solution Building Blocks لتنفيذ القدرة.

مثال: ABB لإدارة الهوية يطلب Authentication وAuthorization وAudit دون تسمية منتج.
تمييز مهم: ABB يحدد الحاجة المنطقية؛ SBB يحدد التنفيذ الفعلي.

A — Architecture Structure

Definitions 4.10–4.21 — Continuum وADM وDomain وFramework وViews
⌄
4.10

Architecture Continuum

متصل المعماريات

آلية تصنيف للأصول المعمارية من العام والأساسي إلى القطاعي ثم الخاص بالمؤسسة، مع زيادة التخصص والتفصيل.

مثال: Reference Model عام → Architecture حكومية → Architecture صحية → Architecture الهيئة.
تمييز مهم: جزء من Enterprise Continuum ويركز على المعماريات لا الحلول المنفذة.
4.11

Architecture Development Method (ADM)

منهج تطوير المعمارية

قلب TOGAF: منهج متعدد المراحل وتكراري لتطوير Enterprise Architecture واستخدامها لتوجيه التحول وحوكمته.

مثال: دورة تبدأ بالرؤية ثم Business/Data/Application/Technology ثم الهجرة والحوكمة.
تمييز مهم: ADM ليس Waterfall إلزاميًا ولا تسلسلًا جامدًا.
4.12

Architecture Domain

مجال معماري

المنطقة المعمارية محل الدراسة. المجالات الأساسية في TOGAF هي Business وData وApplication وTechnology.

مثال: Security قد يعبر المجالات الأربعة بدل أن يكون جزيرة منفصلة.
تمييز مهم: Domain يحدد موضوع التحليل، وليس بالضرورة قسمًا تنظيميًا.
4.13

Architecture Framework

إطار المعمارية

هيكل مفاهيمي يساعد على تخطيط Architecture وتطويرها وتنفيذها وحوكمتها واستدامتها.

مثال: TOGAF Framework يوفر ADM والمحتوى والحوكمة والتقنيات.
تمييز مهم: Framework أوسع من Method؛ فهو يجمع طريقة ومحتوى ومفاهيم وحوكمة.
4.14

Architecture Governance

حوكمة المعمارية

مراقبة وتوجيه العمل المعماري لضمان النتائج المطلوبة والالتزام بالمبادئ والمعايير والRoadmaps.

مثال: Architecture Board يراجع الحل ويوافق على الاستثناءات ويتابع الالتزام.
تمييز مهم: ليست مجرد Approval؛ تشمل التوجيه والرقابة والمتابعة.
4.15

Architecture Landscape

المشهد المعماري

تمثيل للأصول المعمارية المستخدمة أو المخطط لها في المؤسسة عند نقاط زمنية محددة.

مثال: خريطة تطبيقات اليوم، وحالة انتقالية في 2027، وTarget في 2029.
تمييز مهم: Landscape يصف الواقع أو المخطط عبر الزمن، وليس Repository كاملًا.
4.16

Architecture Level

المستوى المعماري

درجة Granularity تستخدم لتقسيم Architecture Landscape إلى مستويات مثل Strategic وSegment وCapability.

مثال: رؤية تنفيذية عالية المستوى مقابل تفاصيل برنامج أو نظام.
تمييز مهم: Level يصف درجة التفصيل؛ Partition يقسم النطاق إلى أجزاء يمكن إدارتها.
4.17

Architecture Model

نموذج معماري

تمثيل مبسط أو مصغر أو مجرد لموضوع معماري بهدف الفهم والتحليل.

مثال: Application Interaction Model يوضح تبادل الخدمات بين الأنظمة.
تمييز مهم: Model جزء من View، وليس بالضرورة وصف Architecture كامل.
4.18

Architecture Partition

قسم معماري

جزء من Architecture تم فصله لتسهيل تطويره وإدارته مع الحفاظ على العلاقات والحدود.

مثال: تقسيم Landscape إلى قطاع الصحة، التمويل، والموارد البشرية.
تمييز مهم: Partition قائم على تقسيم المسؤولية أو النطاق؛ لا يساوي Level.
4.19

Architecture Principle

مبدأ معماري

عبارة نوعية عن Intent يجب أن تلتزم بها Architecture وتوجه القرارات.

مثال: Data is an Asset أو Reuse before Buy before Build.
تمييز مهم: المبدأ يوجه القرار ولا يصف منتجًا أو تصميمًا تفصيليًا.
4.20

Architecture View

منظر معماري

تمثيل للنظام من منظور مجموعة مترابطة من Concerns.

مثال: Security View يعرض Trust Zones ومسارات البيانات والControls.
تمييز مهم: View هو الناتج الفعلي؛ Viewpoint يحدد قواعد إنشائه.
4.21

Architecture Viewpoint

وجهة نظر معمارية

مواصفة القواعد والاتفاقيات المستخدمة لإنشاء وتفسير واستخدام نوع معين من Views لمعالجة Concerns محددة.

مثال: Viewpoint تنفيذي يحدد الجمهور والModels والNotation اللازمة لعرض القرار.
تمييز مهم: Viewpoint يشبه الوصفة؛ View يشبه الناتج الذي تم إعداده بها.

A–C — Vision, Content & Business

Definitions 4.22–4.33 — الرؤية وArtifacts وBaseline وBusiness Architecture والقدرات
⌄
4.22

Architecture Vision

رؤية المعمارية

وصف موجز للTarget Architecture وقيمتها للأعمال والتغييرات الناتجة عنها، ويضع طموحًا وحدودًا للتطوير التفصيلي.

مثال: رؤية لمنصة موحدة تقلل زمن التوريد وتوفر بيانات مركزية.
تمييز مهم: ليست Target Architecture تفصيلية؛ بل صورة عالية المستوى ومبرر أعمال.
4.23

Artifact

أثر أو منتج معماري

منتج عمل يصف جانبًا من Architecture، وغالبًا يكون Catalog أو Matrix أو Diagram.

مثال: Application Portfolio Catalog أو Data Entity Matrix.
تمييز مهم: Artifact يصف Building Blocks وقد يكون جزءًا من Deliverable.
4.24

Baseline

خط الأساس

مواصفة تمت مراجعتها والموافقة عليها رسميًا وتصبح أساسًا للتطوير أو التغيير، ولا تعدل إلا عبر Change Control.

مثال: Baseline لتطبيقات المؤسسة في تاريخ اعتماد الدراسة.
تمييز مهم: Baseline ليست مجرد Current State غير موثق؛ يجب أن تكون معتمدة.
4.25

Boundaryless Information Flow™

تدفق المعلومات بلا حدود غير ضرورية

حالة مستهدفة تتيح الوصول إلى معلومات متكاملة لتحسين العمليات بما يتوافق مع احتياجات المؤسسة.

مثال: وصول الجهة الصحية والمخزن والمشتريات إلى بيانات موحدة وفق الصلاحيات.
تمييز مهم: لا يعني إلغاء الأمن أو منح الجميع وصولًا مفتوحًا.
4.26

Building Block

لبنة بناء

مكوّن يمكن إعادة استخدامه ودمجه مع مكونات أخرى لتكوين Architectures وحلول، ويتطور تفصيله عبر المراحل.

مثال: خدمة إشعارات، قدرة إدارة موردين، أو منصة تكامل.
تمييز مهم: قد يكون ABB منطقيًا أو SBB تنفيذيًا.
4.27

Business Architecture

معمارية الأعمال

تمثيل متكامل متعدد الأبعاد للقدرات والقيمة والمعلومات والهيكل التنظيمي وعلاقاتها بالاستراتيجية والمنتجات والسياسات والعمليات والمبادرات وأصحاب المصلحة.

مثال: ربط هدف تقليل النقص بقدرات Forecasting وInventory وProcurement.
تمييز مهم: أوسع من Process Modeling؛ تربط عناصر الأعمال ببعضها وبالمجالات الأخرى.
4.28

Business Capability

قدرة أعمال

قدرة محددة تمتلكها المؤسسة أو تتبادلها لتحقيق غرض معين، بصرف النظر عن كيفية تنفيذها أو مكانها التنظيمي.

مثال: Supplier Management أو Demand Forecasting.
تمييز مهم: Capability مستقرة نسبيًا؛ Process يشرح كيف تُمارس القدرة.
4.29

Business Function

وظيفة أعمال

مجموعة من سلوكيات الأعمال جُمعت وفق معيار معين وغالبًا ترتبط بالهيكل التنظيمي.

مثال: Finance Function أو Customer Service Function.
تمييز مهم: Function تميل لمحاذاة التنظيم؛ Capability تتمحور حول ما تستطيع المؤسسة فعله.
4.30

Business Governance

حوكمة الأعمال

ضمان أن العمليات والسياسات وتشغيلها تحقق النتائج المطلوبة وتلتزم باللوائح ذات الصلة.

مثال: مراجعة سياسات الاعتماد والتوريد والتأكد من الالتزام المالي والتنظيمي.
تمييز مهم: تركز على الأعمال؛ Architecture Governance تركز على العمل والقرارات المعمارية.
4.31

Business Model

نموذج الأعمال

وصف منطق كيفية خلق المؤسسة للقيمة وتقديمها والحصول على العائد أو المنفعة منها.

مثال: منصة رقمية تربط الموردين بالجهات وتخفض تكلفة المعاملة.
تمييز مهم: يشرح منطق القيمة؛ ليس هو Process Map أو Organization Chart.
4.32

Business Service

خدمة أعمال

سلوك أعمال مميز ومغلف يدعم المؤسسة أو يقدم قيمة داخلية أو خارجية.

مثال: خدمة تسجيل مورد أو خدمة طلب منتج طبي.
تمييز مهم: Business Service قد تعتمد على Application Services متعددة.
4.33

Capability

قدرة

إمكانية يمتلكها شخص أو مؤسسة أو نظام للقيام بشيء معين.

مثال: النظام لديه قدرة على مطابقة الطلبات، والمؤسسة لديها قدرة إدارة المخزون.
تمييز مهم: تعريف عام؛ Business Capability تطبيقه داخل سياق الأعمال.

C–F — Capability, Enterprise & Framework

Definitions 4.34–4.46 — Capability Architecture والاتصالات والبيانات والمخرجات وEnterprise
⌄
4.34

Capability Architecture

معمارية القدرة

Architecture تشرح القدرات التي تمتلكها المؤسسة والعناصر المطلوبة لتحقيقها أو تطويرها.

مثال: Architecture لقدرة إدارة الأصول الطبية عبر العمليات والبيانات والأنظمة.
تمييز مهم: تركز على قدرة معينة وقد تعبر المجالات الأربعة.
4.35

Capability Increment

زيادة أو شريحة قدرة

جزء منفصل من Capability Architecture يقدم قيمة محددة، ومع اكتمال جميع الIncrements تتحقق القدرة كاملة.

مثال: الإصدار الأول يوفر تسجيل الأصول، والثاني الصيانة، والثالث التحليلات.
تمييز مهم: يسمح بتقديم القيمة تدريجيًا بدل انتظار الحل الكامل.
4.36

Communications and Stakeholder Management

إدارة الاتصال وأصحاب المصلحة

إدارة احتياجات Stakeholders في ممارسة Enterprise Architecture وتنفيذ الاتصال بين الممارسة وأصحاب المصلحة ومستهلكي خدماتها.

مثال: خطة رسائل واجتماعات وتقارير مختلفة للإدارة والفرق والموردين.
تمييز مهم: ليست إرسال تحديثات فقط؛ تشمل فهم التأثير والدعم والمقاومة.
4.37

Concern

اهتمام صاحب المصلحة

مسألة أو مصلحة في النظام تهم Stakeholder، وقد تتعلق بالأداء أو الأمن أو التكلفة أو التطور أو الاعتمادية.

مثال: مدير التشغيل يهتم بالتوافر، ومدير الأمن يهتم بحماية البيانات.
تمييز مهم: Concern أوسع من Requirement؛ يُحوّل التحليل الاهتمام إلى متطلبات قابلة للقياس.
4.38

Course of Action

مسار عمل

توجيه وتركيز مشتق من الأهداف الاستراتيجية لاختيار ما ستفعله المؤسسة لتحقيق القيمة.

مثال: توحيد Master Data قبل استبدال التطبيقات.
تمييز مهم: يمثل Direction؛ Roadmap ينظم التغيير زمنيًا، وWork Packages تنفذه.
4.39

Data Architecture

معمارية البيانات

وصف أنواع ومصادر البيانات الرئيسية، والأصول المنطقية والمادية، والموارد اللازمة لإدارة البيانات.

مثال: تعريف Master Data للأصناف والجهات والموردين ومساراتها وملكيتها.
تمييز مهم: لا تساوي Database Design فقط؛ تشمل المعنى والملكية والجودة والLifecycle.
4.40

Deliverable

مخرج رسمي قابل للتسليم

منتج عمل معماري محدد تعاقديًا، يراجع ويعتمد ويوقع عليه Stakeholders رسميًا.

مثال: Architecture Definition Document أو Implementation and Migration Plan.
تمييز مهم: Deliverable قد يحتوي عدة Artifacts ويخضع للSign-off.
4.41

Digital Architecture

المعمارية الرقمية

Architecture شاملة تمزج Enterprise Architecture مع تقنيات ومجالات رقمية مثل البيانات والاتصالات وIoT والأمن والذكاء الاصطناعي والروبوتات لتقديم خدمات تشغيلية.

مثال: منظومة مستشفى ذكي تجمع IoT وAI والبيانات والتطبيقات والبنية التحتية.
تمييز مهم: لا تعني مجرد تحويل الخدمة إلى Web أو Mobile.
4.42

Enterprise

المؤسسة

أعلى نطاق وصفي عادةً لكيان يضم المهام والوظائف، وقد يمتد عبر عدة منظمات لها أهداف مشتركة.

مثال: منظومة الإمداد الصحي قد تشمل هيئة وموردين وجهات ومخازن.
تمييز مهم: Enterprise لا تعني دائمًا شركة قانونية واحدة.
4.43

Enterprise Architecture Service

خدمة المعمارية المؤسسية

عنصر مغلف من Architecture Capability يقدم وظيفة معمارية محددة لعميل أو صاحب مصلحة.

مثال: خدمة Architecture Review أو Roadmap Development أو Capability Assessment.
تمييز مهم: تحول ممارسة EA من نشاط مبهم إلى Service Catalog واضح.
4.44

Enterprise Continuum

المتصل المؤسسي

آلية لتصنيف Architectures وSBBs أثناء تطورها من العام إلى الخاص أو العكس، وتضم Architecture Continuum وSolutions Continuum.

مثال: تصنيف Reference Architecture عامة ثم حل قطاعي ثم حل مؤسسي.
تمييز مهم: Continuum يصنف الأصول؛ Repository يخزنها ويديرها.
4.45

Foundation Architecture

معمارية تأسيسية

Building Blocks عامة وعلاقات ومبادئ توفر قاعدة لبناء Architectures أكثر تخصصًا.

مثال: هوية واتصالات وأمن وتكامل كقدرات تأسيسية عامة.
تمييز مهم: ليست معماريتك النهائية؛ هي نقطة انطلاق قابلة للتخصص.
4.46

Framework

إطار

هيكل للمحتوى أو العملية يستخدم لتنظيم التفكير وضمان الاتساق والاكتمال.

مثال: Framework للحوكمة أو Framework للمحتوى المعماري.
تمييز مهم: مصطلح عام؛ Architecture Framework تطبيقه على العمل المعماري.

G–P — Analysis, Information & Modeling

Definitions 4.47–4.62 — Gap والحوكمة والمعلومات وInteroperability والنمذجة والأهداف والPatterns
⌄
4.47

Gap

فجوة

بيان بالاختلاف بين حالتين، ويستخدم خصوصًا لمقارنة Baseline وTarget.

مثال: لا توجد حاليًا خدمة MDM بينما Target يتطلبها.
تمييز مهم: الفجوة قد تكون مكونًا جديدًا أو شيئًا يجب إزالته أو تغييره.
4.48

Governance

الحوكمة

مراقبة وتوجيه الإدارة لضمان تحقيق النتائج المطلوبة للأعمال أو بيئة IS/IT.

مثال: تحديد من يقرر، من يراجع، كيف تقبل الاستثناءات، وكيف تقاس النتائج.
تمييز مهم: Governance توجه وتراقب؛ Management تنفذ وتدير يوميًا.
4.49

Information

المعلومات

تمثيل أو تواصل للحقائق أو البيانات أو الآراء بأي وسيط، نصيًا أو رقميًا أو بصريًا أو صوتيًا.

مثال: تقرير استهلاك، Dashboard، ملف بيانات، أو تسجيل صوتي.
تمييز مهم: Data تصبح Information عندما تقدم معنى وسياقًا قابلًا للاستخدام.
4.50

Information Technology (IT)

تقنية المعلومات

إدارة دورة حياة المعلومات والتكنولوجيا المرتبطة بها داخل المؤسسة.

مثال: اختيار وتشغيل وصيانة وإحلال المنصات والأنظمة والبيانات.
تمييز مهم: IT ليست الأجهزة فقط؛ تشمل Lifecycle للمعلومات والتقنية.
4.51

Interoperability

قابلية التشغيل البيني

قدرة أنظمة أو مكونات على تبادل المعلومات والخدمات واستخدامها والعمل معًا بفعالية.

مثال: نظام المخازن يرسل بيانات موحدة للنظام المالي ويستخدم الرد تلقائيًا.
تمييز مهم: التبادل وحده غير كافٍ إذا لم يفهم الطرف الآخر المعنى ويستخدمه.
4.52

Logical

منطقي

وصف مستقل عن التنفيذ أو المنتج الفعلي، يبين الوظائف والعلاقات المطلوبة دون اختيار تقنية محددة.

مثال: Logical Data Model أو Logical Application Component.
تمييز مهم: Logical يجيب How بصورة مستقلة عن المورد؛ Physical يحدد With What.
4.53

Metadata

البيانات الوصفية

بيانات تصف خصائص بيانات أو كيان آخر، مثل الاسم والنوع والمالك والمصدر والجودة.

مثال: تعريف عمود GTIN ونوعه ومصدره وقاعدة التحقق منه.
تمييز مهم: Metadata تساعد على الفهم والحكم والإدارة، وليست البيانات التشغيلية نفسها.
4.54

Metamodel

ما وراء النموذج

نموذج يحدد أنواع الكيانات المستخدمة في Architecture Description وخصائصها والعلاقات الأساسية بينها.

مثال: Driver يرتبط Goal، وGoal يرتبط Capability، وCapability تدعمها Services.
تمييز مهم: Metamodel يحدد ما يمكن نمذجته؛ Notation تحدد كيف يظهر بصريًا.
4.55

Method

منهج

نهج محدد وقابل للتكرار لمعالجة نوع معين من المشكلات.

مثال: ADM Method لتطوير Architecture.
تمييز مهم: Method يشرح كيفية العمل؛ Framework يشمل Method وعناصر أخرى.
4.56

Modeling

النمذجة

بناء Models لتمثيل موضوع بطريقة تدعم التفكير والفهم واستخلاص Insight ووضوح جوهره.

مثال: رسم Capability Map أو Data Flow Model.
تمييز مهم: الغرض ليس الرسم ذاته؛ بل تحسين الفهم والقرار.
4.57

Model Kind

نوع النموذج

الاتفاقيات والقواعد الخاصة بنوع Modeling معين، ويحدد Viewpoint الأنواع المستخدمة بينما يحتوي View على Models فعلية.

مثال: Process Model Kind أو Application Interaction Model Kind.
تمييز مهم: Model Kind هو النوع أو القواعد؛ Model هو Instance فعلي.
4.58

Objective

هدف محدد

غاية تنظيمية مصاغة بطريقة SMART: محددة وقابلة للقياس وقابلة للتنفيذ وواقعية ومحددة زمنيًا.

مثال: خفض زمن معالجة الطلب 30% قبل نهاية السنة.
تمييز مهم: Goal قد يكون عامًا؛ Objective يحوله إلى نتيجة قابلة للقياس.
4.59

Pattern

نمط

تقنية تضع Building Blocks في سياق وتوضح حلًا متكررًا لمشكلة وكيف ومتى ولماذا يستخدم وما Trade-offs.

مثال: Integration Pattern مثل Publish/Subscribe.
تمييز مهم: Building Blocks هي الأشياء؛ Pattern يوضح طريقة تركيبها واستخدامها.
4.60

Physical

مادي أو تنفيذي

وصف حقيقي ملموس أو مرتبط بتقنية ومنتج وتنفيذ فعلي.

مثال: اسم المنتج والإصدار والخادم وموقع النشر.
تمييز مهم: Physical يحقق Logical Architecture.
4.61

Principle

مبدأ

مرادف للمفهوم المحدد في Architecture Principle داخل هذا السياق.

مثال: Cloud First مع شروط واضحة.
تمييز مهم: المبدأ يحدد Intent مستدامًا، وليس إجراءً تفصيليًا.
4.62

Product

منتج

نتيجة تولدها المؤسسة وتقدمها للعملاء، وقد تجمع مواد وخدمات.

مثال: منصة رقمية كمنتج، أو دواء مع خدمات دعم.
تمييز مهم: Product يركز على القيمة المقدمة ودورة حياته.

R–S — Planning, Services & Solutions

Definitions 4.63–4.74 — Reference Models والمتطلبات والRoadmaps والأدوار والخدمات والحلول
⌄
4.63

Reference Model (RM)

نموذج مرجعي

إطار مجرد لفهم العلاقات المهمة وتوفير دلالات مشتركة تساعد على تطوير معايير ومواصفات متسقة، دون الارتباط بتنفيذ محدد.

مثال: Reference Model لتكامل المعلومات أو لخدمات Cloud.
تمييز مهم: أكثر تجريدًا من Reference Architecture ولا يفرض منتجًا.
4.64

Requirement

متطلب

بيان حاجة واضح غير ملتبس، قابل للاختبار أو القياس، وضروري لقبول الحل.

مثال: يجب أن يعالج النظام 2,000 طلب في الساعة بنسبة توافر 99.9%.
تمييز مهم: Concern يصبح Requirement عندما يصاغ بصورة قابلة للتحقق.
4.65

Roadmap

خارطة طريق

خطة مجردة لتغيير الأعمال أو التكنولوجيا عبر عدة تخصصات وسنوات، تبين التتابع والتوقيت والعلاقات.

مثال: Roadmap لتوحيد البيانات ثم التكامل ثم إحلال التطبيقات.
تمييز مهم: ليست Project Plan تفصيلية؛ تقدم اتجاهًا وتتابعًا عالي المستوى.
4.66

Role

دور

السلوك المتوقع من Actor أو الجزء الذي يلعبه في Process، وكذلك مساهمة الفرد في المنظمة باستخدام مهاراته وخبرته.

مثال: الموظف Actor يؤدي Role مقدم الطلب وقد يؤدي Role المراجع أيضًا.
تمييز مهم: Actor واحد قد يؤدي عدة Roles، وRole قد يؤديه Actors مختلفون.
4.67

Segment Architecture

معمارية قطاع أو شريحة

وصف رسمي تفصيلي لمنطقة داخل Enterprise يستخدم على مستوى Program أو Portfolio لتنظيم ومواءمة التغيير.

مثال: Architecture لقطاع المستشفيات أو Portfolio سلسلة التوريد.
تمييز مهم: أكثر تفصيلًا من Strategic Architecture وأوسع عادةً من Solution Architecture.
4.68

Service

خدمة

سلوك مغلف يقدم وظيفة محددة استجابة لطلب من Actor أو Service أخرى، وله Interface ووصف.

مثال: خدمة التحقق من أهلية المورد.
تمييز مهم: الخدمة تصف ما يقدم؛ تنفيذها قد يعتمد على Components متعددة.
4.69

Service Orientation

التوجه الخدمي

النظر إلى Enterprise أو System أو Building Block من زاوية الخدمات التي يقدمها ويستهلكها.

مثال: وصف إدارة المخزون كمجموعة خدمات بدل تطبيق واحد مغلق.
تمييز مهم: هو طريقة تفكير؛ SOA هو Architectural Style يدعمها.
4.70

Service-Oriented Architecture (SOA)

المعمارية الموجهة للخدمات

أسلوب معماري يدعم Service Orientation وتنظيم القدرات في خدمات ذات Interfaces واضحة.

مثال: خدمات طلب وInventory وPayment مستقلة وقابلة لإعادة الاستخدام.
تمييز مهم: SOA أوسع من Web Services ولا يشترط تقنية واحدة.
4.71

Service Portfolio

محفظة الخدمات

مجموعة منظمة من الخدمات وقد تتضمن تعريف Interfaces، وتستخدم لتحديد احتياجات Building Block أو System.

مثال: قائمة خدمات الموردين والمخزون والتقارير مع وصف كل Interface.
تمييز مهم: Portfolio يدير المجموعة ككل، لا خدمة واحدة.
4.72

Solution Architecture

معمارية الحل

وصف لنشاط أو عملية أعمال محددة ومركزة وكيف تدعمها نظم المعلومات والتكنولوجيا.

مثال: Solution Architecture لنظام تتبع الأصول الطبية.
تمييز مهم: أضيق من Segment وStrategic Architecture ويركز على حل محدد.
4.73

Solution Building Block (SBB)

لبنة بناء حل

مكوّن مادي أو خاص بالتنفيذ يحقق جزءًا أو كل ABB منطقي واحد أو أكثر.

مثال: منتج IAM محدد يحقق ABB إدارة الهوية.
تمييز مهم: SBB يمكن أن يكون Business أو Application أو Technology.
4.74

Solutions Continuum

متصل الحلول

آلية تصنيف للمكونات والArtifacts الموجودة في Solutions Landscape أو Reference Library من العام إلى الخاص.

مثال: منتج عام → حل مشترك → حل قطاعي → Deployment خاص بالمؤسسة.
تمييز مهم: يركز على التنفيذ والحلول، مقابل Architecture Continuum الذي يركز على الوصف المنطقي.

S–W — Stakeholders, Technology & Delivery

Definitions 4.75–4.88 — Stakeholders والمعايير ومستويات Architecture والتكنولوجيا والتحول والقيمة
⌄
4.75

Stakeholder

صاحب مصلحة

فرد أو فريق أو Organization أو فئة لديها مصلحة في System.

مثال: CIO، مستخدم، جهة رقابية، مورد، أو مريض.
تمييز مهم: ليس فقط صاحب القرار؛ يشمل كل من يؤثر أو يتأثر.
4.76

Standards Library

مكتبة المعايير

مجموعة معايير تستخدم لتعريف الخدمات والمكونات الخاصة بالOrganization-Specific Architecture.

مثال: معايير API وSecurity وDatabase وCloud المعتمدة.
تمييز مهم: جزء من Architecture Repository وتوجه الحلول الجديدة.
4.77

Strategic Architecture

المعمارية الاستراتيجية

وصف رسمي موجز للمؤسسة يوفر إطارًا لتنظيم التشغيل والتغيير ورؤية تنفيذية طويلة المدى لتحديد الاتجاه.

مثال: خريطة خمسية للقدرات والمنصات الرئيسية على مستوى الهيئة.
تمييز مهم: أعلى مستوى وأطول أفقًا من Segment وSolution Architecture.
4.78

Target Architecture

المعمارية المستهدفة

وصف حالة مستقبلية ترغب المؤسسة في الوصول إليها، وقد توجد حالات مستقبلية متعددة ضمن Roadmap.

مثال: Target 2029 لمنظومة متكاملة وموحدة البيانات.
تمييز مهم: يمكن أن تسبقها Transition Architectures متعددة.
4.79

Taxonomy of Architecture Views

تصنيف المناظر المعمارية

مجموعة منظمة لكل Architecture Views ذات الصلة بArchitecture معينة.

مثال: تصنيف Views إلى Executive وBusiness وData وSecurity وOperations.
تمييز مهم: يساعد على التأكد من تغطية Concerns وعدم تكرار Views عشوائيًا.
4.80

Technology Architecture

معمارية التكنولوجيا

وصف بنية وتفاعل Technology Services وTechnology Components التي تمكّن التطبيقات والبيانات والأعمال.

مثال: Cloud، Network، Middleware، Observability، وIdentity Infrastructure.
تمييز مهم: لا تقتصر على Hardware؛ تشمل الخدمات والمعايير والمنصات.
4.81

Technology Component

مكوّن تكنولوجي

Building Block للبنية التحتية يدعم Application أو Data Components عبر Technology Services، وقد يمثل فئة منتج أو منتجًا محددًا.

مثال: Database Platform أو Message Broker أو Kubernetes Cluster.
تمييز مهم: قد يكون Generic في Logical Architecture أو Specific في Physical Architecture.
4.82

Technology Service

خدمة تكنولوجية

قدرة تقنية لازمة لتوفير بنية تحتية تمكّن تشغيل التطبيقات.

مثال: Compute Service أو Messaging Service أو Backup Service.
تمييز مهم: الخدمة هي القدرة المقدمة؛ Component هو ما يقدمها.
4.83

Transition Architecture

معمارية انتقالية

وصف رسمي لحالة Architecture عند نقطة زمنية مهمة بين Baseline وTarget.

مثال: بعد توحيد الهوية وقبل إحلال التطبيقات القديمة.
تمييز مهم: تُستخدم واحدة أو أكثر لتقسيم رحلة التحول إلى حالات قابلة للإدارة.
4.84

Value Stream

مسار القيمة

تمثيل لمجموعة أنشطة من البداية إلى النهاية تنتج نتيجة كاملة لعميل أو Stakeholder أو End User.

مثال: من طلب الصنف حتى استلامه واستخدامه.
تمييز مهم: يركز على القيمة والنتيجة النهائية، لا حدود الإدارات.
4.85

View

منظر

مرادف Architecture View: تمثيل Architecture من منظور Concerns مترابطة.

مثال: View تشغيلي لفرق الدعم.
تمييز مهم: هو الناتج، وليس مواصفة بنائه.
4.86

Viewpoint

وجهة نظر

مرادف Architecture Viewpoint: القواعد والاتفاقيات المستخدمة لبناء نوع معين من Views.

مثال: Operations Viewpoint يحدد المعلومات والModels التي يحتاجها التشغيل.
تمييز مهم: Viewpoint قابل لإعادة الاستخدام لإنشاء Views متعددة.
4.87

Viewpoint Library

مكتبة وجهات النظر

مجموعة مواصفات Architecture Viewpoints محفوظة في Reference Library داخل Architecture Repository.

مثال: قوالب Viewpoint للأمن والبيانات والإدارة التنفيذية.
تمييز مهم: تسرع الاتساق وإعادة الاستخدام في المشروعات.
4.88

Work Package

حزمة عمل

مجموعة إجراءات لتحقيق Objective أو أكثر، وقد تكون جزءًا من Project أو Project كاملًا أو Program.

مثال: حزمة توحيد Master Data أو حزمة إنشاء Integration Platform.
تمييز مهم: هي وحدة تخطيط وتنفيذ تربط Gaps وCapabilities بالمبادرات.

أزواج امتحانية شائعة

Architecture Level vs. Partition

Level يحدد Granularity؛ Partition يقسم Architecture إلى نطاقات لتسهيل الإدارة.

Framework vs. Method

Framework ينظم المحتوى والعملية والمفاهيم؛ Method نهج قابل للتكرار لمعالجة مشكلة.

Capability vs. Function

Capability تصف ما تستطيع المؤسسة فعله؛ Function تجمع السلوك وغالبًا تتوافق مع الهيكل.

Logical vs. Physical

Logical مستقل عن التنفيذ؛ Physical يحدد منتجات وتقنيات ومكونات حقيقية.

Artifact vs. Deliverable

Artifact يصف جانبًا من Architecture؛ Deliverable منتج رسمي يراجع ويعتمد وقد يحتوي Artifacts.

Architecture vs. Solutions Continuum

الأول يصنف الأوصاف المعمارية؛ الثاني يصنف المكونات والحلول التنفيذية.

10. مراجعة وأسئلة الفصل الرابع

Definition Precision and Practice Questions
⌄
لا تحاول حفظ 88 تعريفًا كجمل منفصلة. احفظها في شبكات: Stakeholder → Concern → Requirement → Viewpoint → View، وBaseline → Transition → Target → Roadmap → Work Package، وABB → SBB.

1) Which term means a specification formally reviewed and placed under change control?

Baseline هو المواصفة المعتمدة التي تصبح أساسًا للتغيير وتخضع لChange Control.

2) What is the main difference between an Actor and a Role?

Actor قد يكون شخصًا أو جهة أو نظامًا، وقد يؤدي أكثر من Role.

3) Which term is implementation-independent?

Logical يصف Architecture دون الارتباط بمنتج أو تنفيذ محدد.

4) Which concept classifies architectures from Foundation to Organization-Specific?

Architecture Continuum يركز على تصنيف Architecture Assets.

5) An ABB is best described as:

ABB منطقي ومستقل عن المورد، بينما SBB تنفيذي.

6) Which term describes the actual representation created according to a Viewpoint?

View هو الناتج الفعلي، وViewpoint يحدد الاتفاقيات.

7) Which item must be unambiguous and testable or measurable?

هذا هو الفارق الأساسي بين Requirement وConcern عام.

8) Which architecture is primarily used at program or portfolio level?

Segment Architecture تنظم وتوائم التغيير في منطقة داخل Enterprise.

9) Which term describes an end-to-end set of activities creating an overall result?

Value Stream يعبر الإدارات ويركز على القيمة النهائية.

10) Which term describes data that explains characteristics of other data?

Metadata هي بيانات وصفية عن البيانات أو الكيانات.

11) Which statement about a Pattern is correct?

Pattern يوضح تركيب Building Blocks وسياق الاستخدام والTrade-offs.

12) Which term is a collection of viewpoint specifications in the Reference Library?

Viewpoint Library تحفظ مواصفات Viewpoints القابلة لإعادة الاستخدام.

13) Which architecture is a focused description of an operation and how IS/IT supports it?

Solution Architecture تركز على نشاط أو حل محدد.

14) Which statement best distinguishes Governance from Management?

Governance تحدد الاتجاه والرقابة والسلطة، بينما Management تدير التنفيذ اليومي.

15) A Work Package can be:

TOGAF يستخدم Work Package بمرونة كوحدة عمل لتحقيق Objectives.
