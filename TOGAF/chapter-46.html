1. من المحاكاة إلى الإتقان

Adaptive Remediation, Not Another Passive Review
⌄

بعد ثلاث محاكاة كاملة، لا تحتاج إلى قراءة المنهج من البداية. تحتاج إلى دورة قصيرة: استدعاء → تشخيص → إصلاح → إعادة اختبار. هذا الفصل يحول الأخطاء إلى خطة علاج قابلة للقياس بدل أن تبقى قائمة ملاحظات طويلة.

Recall

استخرج القاعدة من الذاكرة قبل رؤية الإجابة.

Contrast

قارن المصطلح بأقرب مصطلح يختلط به.

Route

حدد Domain وADM Phase أوGovernance mechanism.

Repair

أعد فقط الأسئلة الخاطئة حتى تثبت القاعدة.

الفكرة المركزية: الخطأ ليس درجة مفقودة؛ إنه إشارة تخبرك أي رابط فيالخريطة الذهنية مازال ضعيفًا.

2. تصنيف الخطأ قبل علاجه

Error Taxonomy
⌄

Knowledge Gap

المعلومة غير موجودة فيالذاكرة أصلًا.

Concept Confusion

تعرف المصطلحين لكنك تخلط الحدود بينهما.

Routing Error

فهمت السيناريو، لكنك وجهته إلىPhase أوTechnique خاطئة.

Reading Error

تجاهلت BEST أو MOST أوكلمة تحدد التوقيت.

Distractor Attraction

اخترت عبارة صحيحة لكنها لا تجيب السؤال مباشرة.

Memory Slip

عرفت القاعدة ثم استدعيت ترتيبًا أواسمًا خاطئًا.

Overthinking

أضفت افتراضات غير موجودة فيالسؤال.

Time Pressure

القرار الصحيح ضاع بسبب بطء المقارنة.

3. الاستدعاء أقوى من إعادة القراءة

Retrieval Practice
⌄

إعادة القراءة تمنحك إحساسًا زائفًا بالألفة. الاستدعاء يكشف هل يمكنك إنتاج القاعدة دون مساعدة. قبل كل مجموعة أسئلة، أغلق الملاحظات وقل بصوتك: ما الغرض؟ ما التوقيت؟ ما أقرب مصطلح؟

قاعدة 20 ثانية

إذا لم تستطع تعريف المصطلح وذكر الفرق عن أقرب بديل خلال 20 ثانية، فهو يحتاج مراجعة نشطة لا قراءة إضافية فقط.

5. Preliminary مقابل Phase A

Build the Capability vs Start the Engagement
⌄

Preliminary Phase

تبني طريقة ممارسة Architecture: Governance، Roles، Principles، Repository، Tailored Framework، Tools.

VS

Phase A

تبدأ مبادرة محددة: Vision، Scope، Stakeholders، Value Proposition، Statement of Architecture Work.

6. Phases B وC وD

Architecture Domain Routing
⌄

Phase B

Capabilities، Value Streams، Organization، Processes، Business Information.

Phase C — Data

Data Entities، Ownership، Lifecycle، Quality، Distribution.

Phase C — Application

Application Services، Portfolio، Interactions، Support for capabilities.

Phase D

Technology Services، Platforms، Infrastructure، Standards، Networks.

7. Phase E مقابل Phase F

Shape the Change vs Commit the Plan
⌄

Phase E

تجميع Gaps فيWork Packages، تحديدTransition Architectures، وصياغةImplementation Strategy وInitial Roadmap.

VS

Phase F

تقييم القيمة والتكلفة والموارد والمخاطر والتبعيات، ثم ترتيب المشاريع واعتمادImplementation and Migration Plan.

8. Phase G مقابل Phase H

Govern the Build vs Govern the Change
⌄

Phase G

Architecture Contract، Compliance Reviews، توجيه فرق التنفيذ، معالجة Deviations أثناء البناء.

VS

Phase H

مراقبة القيمة والتغيرات بعد التنفيذ، معالجة Change Requests، وتحديد الحاجة لدورة ADM جديدة.

9. Requirements Management

The Continuous Hub
⌄

Requirements Management ليست مرحلة لاحقة تضيف قائمة متطلبات. إنها عملية مستمرة تستقبل المتطلبات وتبني Baseline وتراقب التغيير وتجري Impact Assessment وتوجه المتطلب إلىPhase المناسبة وتحافظ علىTraceability.

ظهور Requirement جديد لا يعني تلقائيًا Phase A؛ السؤال الحقيقي هو: ما أثره، وأي مخرج أوPhase يجب تحديثها؟

11. Deliverable وArtifact وBuilding Block

Three Different Content Ideas
⌄

Deliverable

Work Product رسمي يخضع للمراجعة والاعتماد وقد يضم عدةArtifacts.

≠

Artifact

Catalog أوMatrix أوDiagram يمثل جانبًا منArchitecture Description.

Building Block عنصر من عناصرArchitecture أوSolution نفسها، وليس مجرد الرسم أوالوثيقة التي تصفه.

12. ABB مقابل SBB

Requirement-Oriented vs Implementation-Oriented
⌄

ABB

يصف ما تحتاجهArchitecture منوظائف وقدرات وحدود وInterfaces دون ربط ضروري بمنتج.

→

SBB

يصف كيف سيُحقق المطلوب فعليًا منخلال منتج أوتقنية أوتنفيذ محدد.

13. View وViewpoint وModel Kind

What You See vs How You Build It
⌄

Concern

ما يهم Stakeholder.

Viewpoint

قواعد وConventions لإنشاءView.

View

التمثيل الفعلي للArchitecture منمنظور محدد.

Model Kind

نوع النموذج وتقنيته وقواعده.

14. Continuum وRepository وLandscape

Classification, Storage, Current Estate
⌄

Enterprise Continuum

منظور لتصنيف الأصول منالعام إلىالخاص.

Architecture Repository

بنية تخزين وإدارة أصول ومخرجات وقرارات Architecture.

Architecture Landscape

مجموعة Architectures الحالية عبرالمستويات والنطاق والزمن.

Solutions Landscape

الحلول المنفذة أوالمخطط لها التي تحققArchitectures.

15. Stakeholder Management

Power, Interest, Concerns, Engagement
⌄

High Power / High Interest

Manage Closely.

High Power / Low Interest

Keep Satisfied.

Low Power / High Interest

Keep Informed.

Low / Low

Monitor أوMinimal Effort.

16. Principles وPatterns

Decision Rules vs Reusable Solutions
⌄

Architecture Principle

قاعدة عامة مستقرة توجه القرارات، وتُصاغ عادةName وStatement وRationale وImplications.

VS

Architecture Pattern

معرفة قابلة لإعادة الاستخدام تصفProblem وContext وForces وSolution وResulting Context.

17. Gap Analysis

New, Eliminated, Carried Over
⌄

المقارنة ليست مجرد قائمة فروق. العنصر الموجود فيTarget وغير موجود فيBaseline هوNew. الموجود فيBaseline وغير موجود فيTarget هوEliminated. الموجود فيكليهما قد يكونCarried Over أوChanged، وأي نقص فيالمصفوفة قد يكشفOmission.

18. Migration Planning Techniques

From Gaps to Executable Sequence
⌄

تجمع التقنية Implementation Factors، Gaps، Solutions، Dependencies، Project Increments، Transition States، Business Value وRisk. الهدف ليس رسم Target فقط بل تحويل التغيير إلىتسلسل يمكن تنفيذه وتمويله.

19. Readiness وRisk وTrade-Offs

Three Different Decision Problems
⌄

Readiness

هل المؤسسة مستعدة للتحول من حيثSponsorship وFunding وCapacity وCulture؟

Risk

ما Effect وFrequency وMitigation وResidual Risk؟

Trade-Offs

أي بديل يحقق أفضل توازن بينمعايير متنافسة؟

Interoperability

ما المتطلبات اللازمة لكي تعمل الأطراف والأنظمة معًا؟

20. Iteration وArchitecture Levels

Repeat the Work at the Right Level
⌄

Iteration قد تكون بينADM cycles، وبينphases، وداخلphase، وبينأنشطة متزامنة. أماArchitecture Levels فتصف مستوى النطاق والعمق: Strategic ثمSegment ثمCapability. لا تخلط تكرار العمل معمستوىArchitecture.

21. Styles وPartitioning

Adapt the Treatment, Divide the Responsibility
⌄

Architecture Style

تركيز أوأسلوب مثلSecurity أوService-Oriented يؤثر فيModels وViewpoints وTechniques وContent.

VS

Architecture Partition

تقسيم للArchitecture لهBoundaries وOwner وGovernance وعلاقات تكامل واضحة.

22. Governance مقابل Management

Set Direction and Control vs Execute
⌄

Governance

تحدد السلطة والسياسات والضوابط والمساءلة والاستثناءات والتصعيد.

VS

Management

تخطط وتنفذ وتنسق الموارد والأنشطة داخل الحدود المعتمدة.

23. Board وContract وCompliance

Authority, Agreement, Evidence
⌄

Architecture Board

جهة قرار وإشراف واتساق وتصعيد.

Architecture Contract

اتفاق علىDeliverables والجودة وFitness-for-Purpose والمسؤوليات.

فحص التنفيذ مقابلArchitecture وPrinciples وStandards.

Dispensation

استثناء مؤقت ومشروط ولهExpiry ومراجعة.

24. مستويات Conformance

⌄

Compliant

Fully Conformant

Non-conformant

⌄

26. Enterprise Metamodel

The Semantic Skeleton
⌄

Concepts

1) ما الغرض الأوسع منEnterprise Architecture؟

Enterprise Architecture تربط الاتجاه الاستراتيجي بالبنية الحالية والمستهدفة وخطة التحول.

2) أيعبارة تصف Architecture بدقة؟

Architecture هيالبنية والعلاقات والمبادئ؛ وليست مجردوثيقة أوخطة.

3) ما Architecture Description؟

Architecture Description تمثيل موثق للArchitecture وليس Architecture ذاتها.

4) أي عنصر يحدد conventions وmodel kinds لبناءView؟

Viewpoint يحدد قواعد إنشاءView لمعالجةConcerns.

5) ما الذي يربط Stakeholder باختيارViewpoint؟

Concerns هيما يهمStakeholder وتوجه اختيارViewpoints.

6) أيعبارة صحيحة عنDeliverable وArtifact؟

Deliverable مخرج رسمي وقد يحتويCatalogs وMatrices وDiagrams.

7) ما العلاقة الصحيحة بينABB وSBB؟

ABB requirement-oriented، وSBB implementation-oriented.

8) ما الفرق الأدق بينCapability وProcess؟

Capability تركز علىالقدرة، وProcess علىكيفية سيرالعمل.

9) ما الذي يمثل الحالة الحالية؟

Baseline Architecture تصف الحالة الحالية ضمنالنطاق.

10) ما وظيفةTransition Architecture؟

Transition Architecture تمثل حالة وسيطة قابلة للتشغيل.

11) أي اقتران صحيح؟

Continuum يصنف؛ Repository يخزن ويدير.

12) ما الفرق بينContent Framework وEnterprise Metamodel؟

Content Framework ينظم المحتوى، وMetamodel تحدد بنيته الدلالية.
